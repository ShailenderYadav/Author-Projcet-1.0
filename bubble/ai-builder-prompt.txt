Build a Bubble-native web application called BookLeaf Royalty Hub. This is an author royalty dashboard and an operations notification system, NOT a support-ticket app. Build it using Bubble database types, authentication, privacy rules, repeating groups, conditionals and native workflows. Do not embed an external coded application.

Design: calm cream background, forest-green navigation, clean readable cards, warm publishing-company style, desktop and mobile responsive. Pages: login; author dashboard; books; admin authors; author detail; admin notification log. Roles: author and admin. Authors see only their own records. Admins see all records. No visitor may assign themselves admin.

Types: User (native auth, display_name, role, author_profile); Author (author_id, name, email, phone, city, joined_date, owner User); Book (book_id, author Author, owner User, title, isbn, genre, publication_date, status, mrp, available_on list text, print_partner); RoyaltySnapshot (snapshot_id, book Book, author Author, owner User, as_of, author_royalty_per_copy, total_copies_sold, total_royalty_earned, royalty_paid, royalty_pending, last_royalty_payout_date); Payout (author, book, owner, amount, paid_at, reference); NotificationLog (author Author, author_external_id text, owner User, requested_by User, status text, subject text, email_body text, error_message text, delivery_status text, total_earned number, total_paid number, total_pending number, generated_at date, completed_at date, attempt_count number, payload_as_of date). Keep NotificationLog.status as text for external Data API callbacks.

Author dashboard: all own books, latest snapshot per book, aggregate earned/paid/pending. Book row includes title, ISBN, genre, publication date, status, MRP, availability, copies sold, earned, paid, pending, last payout. Green Fully paid if pending zero. Red Overdue only if published, pending positive and last payout older than 90 days, or no payout and publication older than 90 days. Otherwise yellow Pending. Exactly 90 days is not overdue. Production-only books should not be marked overdue. Recompute based on current dates.

Admin authors: search name; filter city and fully paid/pending/overdue; show book counts, total earned, pending totals. Open author detail to see all book and royalty data. Payout history must not invent transactions: imported sample contains cumulative paid amounts and last payout dates only. Show a clear empty ledger state if no transactions exist.

Author detail: Generate & Send Royalty Summary button. Helper says content is generated and saved, with actual email delivery not yet enabled. Disable immediately after click. Guard against existing Queued/Processing log for same author. Create NotificationLog status Queued, then call a private server-side API Connector action to n8n with request_id=this log's unique ID, author_id, as_of=today UTC YYYY-MM-DD, and an author object containing all book royalty facts. Secrets are private connector headers, never page fields or client URLs. Keep n8n URL unset until configured; do not fabricate working integration.

n8n replies asynchronously with accepted flag; UI displays queued state, clears spinner, and polls log for success/failure. Handle webhook errors visibly and mark failures. After 3 minutes without completion show timeout and stop indefinite loading, without overwriting already completed logs. Retry Failed jobs with same ID, never duplicate active jobs. Bulk Generate queues one invocation per author whose pending balance is positive, using same guarded action.

Notification log is admin-only: author, requested/completed dates, status Queued/Processing/Success/Failed, delivery status, attempt count; detail shows generated email text or error. Render email text safely as plain text. Success means generated and stored, not emailed.

Privacy: anonymous users no access. Logged-in authors may find/read only Author/Book/RoyaltySnapshot/Payout records whose owner is Current User. Admin role may find/read necessary records. No author access to NotificationLog. Disable auto-binding and author mutation of role, owner, royalties and log status. Enforce role guards in workflows; redirects alone are not privacy rules.

Do not generate fake source authors or book amounts. Prepared CSVs contain the exact 10-author, 18-book dataset and will be imported separately. Build complete empty/loading/error states. Mark any unconfigured external integrations as incomplete. After generation, list everything requiring manual editor verification, especially privacy rules, external connector credentials, bulk scheduling and callback API access.
